# Bug report: slow chat, 160 s image turns, broken chats, "Thinking in depth" everywhere

**Date:** 2026-11-05 · **Component:** `supabase/functions/chat-proxy` (prod v73), web client · **Fix branch:** `fix/chat-latency`

## Symptoms (as reported)

- Image analysis takes about 160 s.
- Plain chat takes 40–60 s for some users; the owner's own tests take 12–13 s.
- Chats sometimes break: no answer, or a garbled one (see below).
- "Thinking in depth" shows on simple questions such as "what can you do".
- One reply was the model's own drafting notes, cut off mid-word:
  `" direct response. * Follow-up suggestions at the bottom (2-4 in user's voice). 5. **Drafting final text:** "Take-Two`

## Root causes

Evidence comes from the prod function logs (2026-11-04/05), the code, the Supabase secret digests, and live calls with the local keys.

**Why one user sees ~12 s and others 40–60 s:** with B1 everyone shares one free Gemini key. Concurrent users push it into 429/503, every candidate fails slowly (B3), and mobile networks add time on top. The 24-hour log window held mostly the owner's own traffic, so this part is inferred, not measured.

## Fixes (branch `fix/chat-latency`)

| Fix | Where |
|---|---|
| Every Gemini call has a deadline: stream first-token 15 s (vision 12 s), stream total 60 s, one-shot calls 30/45 s, resolver/OCR 8 s. A silent model gives way to the next one. | `streaming.ts` (`streamGemini`, `geminiGenerate`, `raceAbort`), `index.ts`, `visionPipeline.ts` |
| Whole-turn budget: no new model starts after 90 s, and the turn ends with a readable error at 115 s, before the platform kills it at ~150 s. A keepalive frame every 10 s. | `index.ts` handler, `SseWriter.ping()` |
| The client gives up on a stream that has been silent for 45 s and retries. A server `error` event is shown instead of re-running the whole turn. | `src/services/aiProvider.js` |
| Gemini thinking is set per turn: `minimal` for simple/medium text, `low` for deep and vision. The thinking allowance is added on top of the answer budget. | `meshRouter.ts geminiThinking()`, `index.ts geminiBudget()` |
| `MAX_TOKENS` with under 400 visible chars, and replies that are drafting notes ("Drafting final text:", "Constraint checklist", …), count as failures, and the next model answers. | `streaming.ts`, `reasoning.ts looksLikeLeakedPlan()` |
| OCR uses `GEMINI_OCR_MODEL`. `gemini-2.5-flash-lite` and `qwen/qwen3.6-27b` are removed, and agentic routing is off until a working id exists. 503s and timeouts cool the model down. | `visionPipeline.ts`, `meshRouter.ts`, `index.ts` |
| A refused key or account (401/403/402) is remembered for 10 min per isolate and logged once with what to fix. A 429 skips just that model. | `index.ts` |
| Small talk skips web search, history carry-over and the INTEL blocks. The "Thinking in depth" thresholds move to 15 s (server) and 20 s (client). | `index.ts isSmallTalk()`, `gameContext.js` |
| Vision: the steps are silent and the reply is the answer (plus an optional "What I see:" line). Cap 1,800 tokens. Resolver and OCR run in parallel, and OCR overlaps the web search. The HUD crop is skipped for frames under 1000 px tall, using a header check before the WASM decode. The second opinion only runs on non-streaming turns, with a 12 s cap. | `index.ts`, `visionPipeline.ts imageSize()` |
| Void RPCs no longer log a JSON parse error. | `meshDb.ts` |
